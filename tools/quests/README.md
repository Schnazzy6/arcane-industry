# Генератор книги квестов

**Текущие награды:** после `deduplicate.js` работает `rewards.js`. 520 практических заданий
и вех дают предметные припасы плюс фиксированный опыт, 37 подсказок не награждаются.
Пулы и проверка количества описаны в `QUEST-REWARDS-REPORT.md`. Ранние описания политики
«только опыт» ниже относятся к предыдущей итерации и заменены этим слоем.

Работает локально, без загрузки данных из интернета. Node.js; Python нужен только для извлечения
переводов и тегов из уже установленных JAR. Рабочая версия книги: 557 квестов в 13 главах.

## Обновление

1. `python tools/quests/extract_languages.py` — после обновления модов или переводов.
   Нужен установленный Python 3, доступный командой `python`.
2. Обновить `build/server/kubejs/config/recipe-dump.json`, если менялись рецепты (серверный дамп).
3. `node tools/quests/build.js --check` — проверка без изменения игровых файлов.
4. `node tools/quests/build.js` — записать определения в overrides.
5. `node tools/quests/preview.js build/quests-preview.html` — карта для просмотра.
6. `node tools/quests/deploy.js` — установить книгу в текущий Prism 0.1.4 и тестовый сервер.
   Прежние определения сохраняются в `build/quest-backups`; данные команд/игроков не копируются и не удаляются.
7. При остановленном тестовом сервере: `node tools/quests/server-check.js`.
   Запускается существующий локальный тестовый сервер, выполняется временная проверка фильтров,
   затем штатная остановка. Лог — `build/quests-server-check.log`. Существующие настройки сервера не меняются.

## Источники и описание

- `ch_*.js`: основной текст и постоянные ключи квестов; ID вычисляется из ключа.
- `early.js`: дополнительные ветки первых трёх глав, механика и практические советы.
- `load.js`: единая загрузка для сборки, проверки и предпросмотра.
- `polish.js`: исправления прежних текстов, политика ранних наград, автоматическое «Где пригодится».
- `catalog.js`: русские названия (локализация сборки → ru из JAR → en → ID), индексы входов/выходов
  рецептов, раскрытие тегов, жидкости, EU/т и длительность. Поиск:
  `node tools/quests/catalog.js modern_industrialization:bronze_plate --uses`.
  Без `--uses` выводятся способы изготовления.
- Источник `build/quest-languages.json` содержит также ванильные en/ru из клиента и локального кэша Prism.
  `build/quest-tags.json` объединяет определения тегов из JAR и overrides.
- «Где пригодится» содержит до шести выходов рецептов. Это справка о применении, а не рекомендация
  немедленно крафтить поздние вещи. Специальные механики, не представленные обычным рецептом, не индексируются.
- Блочные взаимодействия, NBT и характеристики машин нельзя доказать дампом рецептов; для них нужны игровые проверки.

## Карта и проверки

`layout.js` раскладывает ветки колонками по глубине зависимостей, независимые ветки — по строкам.
Авторские координаты сохраняются, если не включить `force`. В `early.js` между рядами четыре клетки,
между колонками три. Дополнительные ветки начинаются с кликабельной ссылки на исходный этап;
у первого квеста скрыта длинная линия от основной карты. Внутри ветки линии видимы.
**Этот первоначальный вариант заменён оформлением ниже:** копии QuestLink оказались источником
паразитных линий в самой игре и больше не попадают в книгу.

Генератор проверяет существование предметов/зависимостей, уникальность ключей/ID,
циклы, близость квестов и прохождение линий через узлы. Для первых трёх глав дополнительно
проверяются пересечения линий, ссылки рядом с узлами, непустые теги, источники новых производственных
заданий, описания и ограничения наград. Это геометрия центров узлов; отображение длинных названий
и поведение интерфейса нужно смотреть в игре.

## Команда и награды

FTB Quests ведёт задачи через TeamData. `default_consume_items: false` оставляет вещи у игрока;
`default_reward_team: false` означает личное получение награды каждым участником команды.
Названия полей и тип опыта сверены с установленным FTB Quests 2101.1.36.

Первые три главы:

| Глава | Квесты | Суммарный опыт на игрока |
|---|---:|---:|
| Начало пути | 40 | 134 очка |
| Эра пара | 93 | 515 очков |
| Электричество | 100 | 539 очков после устранения повторов |

Обычное предметное задание: 3 очка на старте, 5 в паре/LV; предметная веха — 12;
финал главы — 20. Это **очки**, не уровни: награда не растёт вместе с уровнем игрока.
Задания-галочки первых трёх глав ничего не выдают. Несколько машинных вех дают по 8 факелов.
По одному небольшому случайному набору выдаётся только за финал главы с предметными условиями.
Готовых машин, схем, алмазов и магических ключей в этих наборах нет; повторяемых квестов нет.
Из прочих таблиц также исключены собственные компоненты, открывающие эпохи.
Для команды из четырёх игроков размер одного набора умножается на четыре; это учтено в малых количествах.

Старые ID квестов сохранены. Изменение задач не сбрасывает уже завершённый квест автоматически.
Практическая проверка баланса в выживании и общего прогресса с несколькими игроками ещё требуется.

## Лестница снаряжения

`gear.js` читает действующий `gear-tiers.json` и `ladder-modules.json`. Главы `ch_22_armor.js`
и `ch_23_weapons.js` создают задания только для непустых сочетаний группы и тира:
47 целей брони и 77 целей оружия/инструментов. Каждая цель содержит точный список альтернатив,
скомпилированный через FTB Filter System. Отсутствующие тиры не заполняются выдуманными предметами.
Пустые позиции остаются на карте, а зависимость переходит к ближайшему существующему нижнему тиру.

Есть 14 вводных подсказок групп, восемь отдельных каркасов и 14 реально используемых модулей станций.
Части брони животных не входят в четыре слота игрока. `minecraft:shulker_shell` явно исключён
из фильтра шлемов: реестр относит реагент к голове, но это не боевая броня. Игровые тиры и рецепты
при этом не меняются.

`gear-guide.js` обновляет старый справочник и сохраняет ключи его квестов. `core1`, `core2`, `core3`
перенесены в главу брони с сохранением ID. Получение стола 9×9 больше не зависит в книге от
предварительного получения каркаса, которому нужен этот стол.

Награды новых целей: I–III — 3 очка опыта, IV–VII — 5, VIII–XI — 8, XII — 12.
Каркасы дают 5–8 очков, модули — 5–8. За подсказки наград нет. Ни ящиков,
ни физических предметов новые главы не выдают. Полные главы дают на игрока 342 и 507 очков.
Они необязательны для основного пути; для зачёта достаточно одного предмета каждого выбранного задания.

`validate.js` проверяет полное и однократное покрытие всех 124 сочетаний, соответствие каждого
фильтра реестру, источники каркасов/модулей, бюджет наград и геометрию обеих глав и справочника.
`self-test.js` проверяет отклонение испорченного фильтра и пропущенной ступени.
`server-check.js` прогоняет сформированные выражения установленным FTB Filter System:
все альтернативы должны приниматься, иной тир и иной тип — отклоняться.

## Текущее оформление и устранение повторов

После `polish.js` выполняются `deduplicate.js` и `design.js`. Первый заменяет повторные
предметные задачи справочными заметками без наград и сохраняет их ID. Второй раскладывает
первые три главы по тематическим карточкам в двух колонках, создаёт нативные цветные подложки
и заголовки ChapterImage. Копии QuestLink не используются. Все видимые линии короткие,
горизонтальные или вертикальные; остальные предпосылки записаны в описаниях.

Финалы ранних глав — отдельные вехи с проверенными предметными предпосылками; не требуется
повторно снимать и предъявлять машины. Награда финала сохраняется, чтение обычных заметок ничего не даёт.
`server-check.js` проверяет фактически загруженные флаги линий для всех 557 квестов, 98 элементов
оформления и отсутствие копий. `preview.js` сохраняет итоговую модель в `build/quest-scenes.json`;
`render_preview.py` создаёт обзорные PNG первых трёх глав. Эти изображения не заменяют игровой просмотр.
